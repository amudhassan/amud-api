# Tenant workflow and reporting release

## Behavior

- Guides tenancy registration through contract clauses, confirmation, activation, billing, payment and receipt, retaining current action timestamps and original tenancy dates.
- Applies owner-scoped navigation and accountant contact-only tenant editing; backend write authorization remains authoritative.
- Adds the mainland residential clause draft and shared modal portal to preserve dialog visibility.
- Normalizes lease pagination query strings for Express 5.
- Enables the selected Modern Teal style on the tenant directory, including normal production builds.
- Allows property or finance managers to read occupancy and lease reports within their existing active owner scope. This does not grant property mutation permissions.
- Dashboard shows ended lease counts and up to ten expired terms. Historical expired terms can coexist with a renewed active lease; they do not indicate rent arrears.

## Validation

36 focused Jest tests passed. Disposable PostgreSQL engine checks applied all 41 repository migrations and passed tenancy registration, API billing/payment/receipt integrity, accountant dashboard access and revoked-owner-link denial. Mainland preset validation and owner isolation/rollback checks passed. Desktop/mobile browser checks exercised dashboard expired rows and tenant dialogs. Frontend build and lint completed; existing lint warnings remain.

The complete legacy Jest suite reports nine failures in five suites on both the production baseline and release workspace. They include missing local JWT/database configuration and outdated middleware expectations. This release does not claim the entire suite is green.

## Deployment and data boundary

No schema migrations are added by this release. Deploy backend and frontend from the same main commit. Render auto-deploy is enabled for both existing services.

Preview import, cleanup and database seed commands must not run on production. Imported preview records, CSV monitoring tables, signature image/configuration and local audit files are not copied by this code deployment. Data migration and signature provisioning require separate verified operational steps; do not restore the entire preview database over an existing production database.

Capture the previous live commit for application rollback. A code rollback does not undo database or external side effects. Verify both deployments reach live and test public application/DB health plus unauthenticated API denial. Authenticated owner/accountant verification remains necessary after rollout.
