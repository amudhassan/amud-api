# Preview legacy rental monitoring

The guarded local preview now has a Legacy Rental Monitoring screen for the source tenant register, units/contact details, date-in, monthly source rent and complete historical payment rows. Source status is preserved as a source field, not converted into occupancy or tenant activation. Blank-name/unlinked rows and orphan payments remain visible for reconciliation.

Run `scripts/ux/legacy-rental-monitor.cjs --source-dir DIRECTORY --dry-run` using the existing local acceptance connection. The directory must contain the exact previously imported categories/houses/tenants files plus payments.csv. `--apply` creates a transactional preview snapshot and a finance relationship for the known synthetic staff account. It does not create a password account or grant access to other users. The batch requires the existing profile import hash, known preview identity markers and local acceptance connection guard. Unchanged repeats preserve all reviews and payments; changed sources require separate reconciliation.

After restarting `scripts/ux/lease-accountant-preview.cjs`, use its Staff review URL and open Legacy Rental Monitoring. Search by source ID, tenant name, phone, property or unit; inspect full payment history and record a verified paid-through date with evidence. Reviews use optimistic versions and append actor/time/before/after audit records. Owner finance authorization is required for reads and writes; revoked access is rejected. Blank paid-through means review remains unconfirmed.

The snapshot does not modify canonical leases, invoices, payments, receipts or notifications. Newly recorded canonical payments and invoices for the same tenant/owner are shown separately and are never blindly added to legacy payments. A paid invoice covering the current date is identified separately. User-entered review dates take precedence in the monitoring status. No historical debt, SMS, renewal, signature date, tenancy activation or occupancy is fabricated. Contract registration and billing continue through the existing verified workflows after reconciliation.

Estimates assume all historical payments are rent at the current source monthly price continuously from date-in. They show whole months, remaining amount and estimated end. Missing/invalid date, unknown/zero rent, absent unit, no payments or payment preceding date-in blocks estimation. Fractional months remain unconfirmed. Source dates and payment-entry timestamps are displayed separately. The assessment date uses Africa/Dar_es_Salaam. Estimates are not booked receivables.

The route is mounted only by the preview launcher; the production app does not mount the API. The preview sidebar link is enabled only when the launcher sets its Vite preview flag. No production migration or deployment is involved. All source CSV bytes stay local and out of Git.

Validation: run `legacy-rental-monitor-check.cjs` with the isolated PostgreSQL test setup. Optional `--source-dir` verifies a local export without publishing it; `UX_MONITOR_BROWSER=1` exercises staff history/review on desktop/mobile using the real preview API. Tests cover read-only dry-run, mismatched source, transactional failure rollback, full source preservation, unchanged repeat, audit/version conflicts, owner access/revocation, date math and unchanged canonical financial counts.
